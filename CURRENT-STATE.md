## What to do next

1. Open [the free ChatGPT chat + GitHub guide](docs/CHATGPT-CHAT-FIRST-WORKFLOW.md) and `SETUP.md`.
2. Decide your original storyworld's name, premise and permanent code. Set both YAML routing files to the same code. Review `CREATOR-CONTENT-RIGHTS.md` before collaboration or public sharing.
3. Draft `01-storyworld-core/storyworld.md` from `templates/00-storyworld.md`, with permanent ID `<CODE>-SW-0001` and initial `WORKING` status.
4. Review and save the complete new owner and registry via the GitHub web file editor (no connector or local computer required).
5. After the files are saved, update this **human-readable progress record**. Distinguish what the owner approved, what is merely a proposal, what remains unknown and what contradicts existing canon. Record the actual Git commit only after checking it in GitHub.

## Framework maintenance vs. your storyworld

Framework developer release reports, contributor audit logs, test receipts and developer pull requests concern **Writing Universe Template itself**, not the new universe you create. They must not cause a newly created storyworld to inherit the framework maintainer's release status or unrelated approval decisions. Creators should not need developer tools, optional browser experiments or a paid subscription to write stories.
