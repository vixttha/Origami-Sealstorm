## Scope and limitations

Documentation archive from available conversation and historical receipts. Not a literal platform export, not an exhaustive raw log of tool payloads, no image widget media or internal reasoning. Owner quotations preserve available design statements, with formatting normalization; first installation turns reconstructed from receipts. All assistant proposals and subjective ratings retained as proposals, not verified facts. No source code or private development Bible copied. No new runtime validation, no release, no additional canon approval, no modification to existing branch records.

Archive branch uses an independent scratch tree rooted at existing OS main as parent, so its current contents are only archive documents; it is not an orphan history and does not erase product ancestry. Branch naming chosen for discoverability. No required runtime or CI in documentation-only scope. Formal owner approval of archive wording and migration of creative decisions remain separate.
